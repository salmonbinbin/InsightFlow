# 评测页面发起与自定义运行检查

日期：2026-10-22。本批为用户授权的评测页面补齐，不改变历史阶段的语义验收结论。

## 使用

1. 刷新页面，在右上角选择项目，进入左侧「评测」。
2. 在「发起评测」选择「当前项目运行检查」，适用于任意已保存输入快照的分类或聚类记录。
3. 选择分析阶段和一条已结束的记录，点击「生成检查报告」。报告自动打开，保存到项目运行历史。运行中记录不能选，记录支持分页。
4. 查看样本数、流程成功率、结果关联完整率和失败案例。后续导入的反馈不会进入旧运行的样本分母。
5. 对内置配套演示数据，可改选「内置参考样本评测」。不匹配的自定义数据会被拒绝；标签仍标为未经人工复核。

## 指标边界

当前项目运行检查仅验证既有分析的结构完整性，既不再次调用模型，也不把模型答案作为参考标签。结果关联完整率表示每个输入恰好关联一个保存的分类结果或聚类成员（包含离群项）。重复关联或没有关联会产生失败案例。

报告的「完成」指检查已完成，不代表内容语义正确。无参考答案时分类准确率、意图匹配率、严重度误差、聚类纯度和主题分散程度为 NULL / 未测量。当前尚无自定义人工标签编辑/导入、洞察语义打分或 PRD 质量评测入口。本批只接通分类/聚类的发起与报告查看。

聚类使用 local-hash-v1 时显示测试嵌入说明；结构关联完整不证明语义分组正确。数据来源标为 unverified，未把所有项目自称为合成或生产数据。内容哈希记录评测时的原文快照，不声称验证了分析时历史原文哈希。

## 实现

- 新增 POST /evaluations/run-check，沿用严格请求 schema：project_id、source_run_id、evaluation_type（classification_metrics / cluster_metrics）。
- 新服务只读取 AnalysisRun、Feedback、FeedbackAnalysis、Cluster 和 ClusterMember，事务性新增 evaluation_runs / metrics / cases。报告类型 pipeline_health；计算版本 run-check-v1；无迁移。
- 拒绝跨项目、阶段不符、未结束、缺输入快照、快照数量不符、反馈缺失及结果归属异常。无效请求不写报告。
- 前端新增发起表单、记录分页、提交中禁用、切换项目取消请求和完成后自动打开报告。原参考样本 POST /evaluations 保持兼容。
