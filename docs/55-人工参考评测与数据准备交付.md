日期：2026-10-28。负责人：三文鱼。性质：本批交付记录（人工参考答案评测 + 300条合成数据准备）；本批未提交、未推送、不进入Phase9。

## 1. 结论与范围

本批完成两件事：

1. **人工参考答案评测**：评测页可对某个已结束的分类/聚类运行下载空白标签模板，人工在CSV中填写标签与审核人后上传，系统用该子样本计算确定性指标并生成可回看的报告与逐例对照。
2. **数据准备**：新增300条合成输入与100条待审核材料（`data/synthetic-review-v1/`），用于导入、批处理与标注流程验证。

**本批不做什么：** 不是洞察/PRD语义打分，不实现网页逐行编辑（人工填写CSV），意图自由文本仍未测量；没有模型调用，没有写密钥，没有新迁移，没有新依赖。

**保留的既有结论：** Phase8 **PARTIAL**、最近冻结 Research 质量 **FAIL**、正式用户验收 **NOT MEASURED** 三项均不因本批改变。

## 2. 用户操作

### 2.1 评测页：人工参考答案（分类/聚类）

1. 打开评测页，选择当前项目 → 「人工参考答案评测」区域。
2. 选择阶段（反馈分类 / 聚类）和一条**已结束**的分析记录（`completed` / `partial_failed` / `failed`；运行中记录不可选）。
3. 点「下载标注模板」：CSV保留 `project_id`、`source_run_id`、`feedback_id`、`content_hash`、`content` 列，`review_status` 为 `pending`，标签列为空，**不泄露模型预测**。
4. 人工逐行填写（**两个阶段都必须把 `review_status` 改为 `reviewed` 并填 `reviewer`**，否则上传会被拒）：
   - 分类：`review_status=reviewed`、填 `reviewer`、`feedback_type`（bug / feature_request / ux_issue / performance_issue / pricing_issue / content_issue / positive_feedback / other）、`severity`（1—5），`cluster_label` 留空。
   - 聚类：`review_status=reviewed`、填 `reviewer` 与 `cluster_label`（同一需求用同一标签；相似用词不一定同组），`feedback_type` / `severity` 留空。
   - 可**删除未复核行**，只评估保留下来的子样本。
5. 先在「上传已复核CSV」处选择填写好的CSV文件（页面会显示「已读取：文件名」），再点「生成参考答案评测」→ 打开报告，查看指标与「人工标签与结果对照」（每条的人工标签、审核人、已有结果、是否一致）。

### 2.2 使用300条合成数据

1. 新建合成数据项目，上传 `data/synthetic-review-v1/feedback.csv`（300条）。
2. 需要人工评测时，按2.1下载**该Run绑定**的模板；可参考 `review-100.csv` 挑选候选ID，填完后上传。
3. **离线 `review-100.csv` 没有项目/Run列，不能直接上传**（会被拒），必须用页面下载并填写后的模板。
4. 修改标签再次上传会**新增**报告，不覆盖旧报告。

## 3. 实现范围

### 3.1 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/evaluations/reference-template` | 下载当前项目+已结束Run的空白CSV模板 |
| POST | `/evaluations/reference-review` | 上传已复核CSV，生成评测报告 |
| GET | `/evaluations/{id}/reference-review` | 读取逐例标签对照（`project_id` 必填、分页） |

校验规则：CSV最大2MiB、最多10000行；必须属于同一项目与所选Run；`feedback_id` 未知/重复/不在运行输入中一律拒绝；`content_hash` 与原文漂移拒绝；标签非法或未填 `reviewed`/审核人拒绝；上传失败整体回滚，不留半份报告。

### 3.2 数据与快照

- 评测写入独立的 evaluation 表，**不复制 Raw Feedback**，不改源分析结果，历史报告不被覆盖。
- 标签、审核人、已有结果快照按上传行为保存；标签状态固定为 `user_reviewed_reference_not_formal_acceptance`。
- 服务**不认证审核人身份**，标签仅表示上传者声明已复核，不冒称正式项目验收。
- 无新数据库迁移，无新依赖。

### 3.3 前端

评测页新增「人工参考答案评测」面板与「人工标签与结果对照」区块：防重复提交、换项目时终止在途请求、文件读取竞态处理、错误可读提示；报告区分「本次复核 N 条 / 原运行输入 M 条」。

### 3.4 数据文件

`data/synthetic-review-v1/`：20个设计主题 × 3种表达 × 5种情境 = 300条；`review-100.csv` 100条待审核（`pending`、标签留空）；`groups.csv` 按整主题分组切分 train/validation/test = 180/60/60，防止近主题跨集泄漏；`manifest.json` 记录版本、条数、来源、限制与SHA-256。生成脚本 `backend/scripts/build_review_dataset.py`，输出目录已存在时拒绝覆盖；不调用模型、不访问数据库。

> **限制：** 模板合成会造成高度相似表达；`groups.csv` 的设计分组**不是人工真值**，模板合成**不是**自然业务质量证明。旧的12条CSV未被覆盖。

## 4. 指标口径

### 4.1 分类（`classification_metrics`）

- `feedback_type_accuracy`：分母为**本次已复核样本数**；缺失预测的样本计为不命中（计错），不剔除。
- `feedback_type_macro_f1`：**逐类别F1的宏平均**（unweighted macro F1），不是按样本数直接相除；只对出现过的标签类别计算，缺失预测计为该类FN。其 `sample_count` 是已复核样本数，而取值是类别级宏平均，不能把 `sample_count` 当作F1的分母。
- `severity_exact_match`：分母为**本次已复核样本数**；缺失预测或缺失严重度计为不匹配。
- `severity_mae`：**条件指标**——只对存在有效预测的样本计算绝对误差均值，`sample_count` 是**条件样本数**（不是全部已复核样本数）；缺失预测/缺失严重度的计数与更宽分母记录在 details 中。条件分母与全量分母不可混读。
- 各指标的 `sample_count` 含义并不相同：准确率与严重度精确匹配是已复核样本数，MAE是条件样本数，宏F1的取值是类别级平均。比较时须看各自定义。
- `intent_exact_match`：`value=NULL`、`sample_count=0`，原因是意图为自由文本、没有受控词表（不测）。
- `pipeline_success_rate` / `pipeline_failure_stage_count`：来自**原Run**的计数，不是本次子样本。

### 4.2 聚类（`cluster_metrics`）——本批修复分母口径

- 语义指标（纯度、覆盖、碎片化、过合并率）只在**含已复核成员的簇**上计算：未复核成员被过滤，过滤后为空的簇直接丢弃，因此未复核簇既不进入过合并率分母，也不稀释比值。
- `cluster_over_merge_ratio`：分母 = 含已复核成员的簇数。混合簇（两条人工标签不同）应为 `1.0`；所有已标注簇纯净时为 `0.0`。
- `cluster_purity_micro`：分母 = 已标注成员数。
- 无可测量样本时（被复核反馈没有预测结果）：过合并率与纯度为 **`value=NULL` + `sample_count=0`**，不是假0。
- `cluster_count`：**仍为原Run的全量簇数**，口径写在 details：`total_predicted_clusters`（全量）、`labelled_predicted_clusters`（含已复核成员的簇）、`scope=all_source_run_clusters`。
- 每个聚类指标的 details 都带 `labelled_predicted_clusters` 与 `total_predicted_clusters`；所有指标另带 `reviewed_count` 与 `source_input_count`。

### 4.3 分母显示

报告同时显示**子样本分母**（`reviewed_count`）与**原Run分母**（`source_input_count`）。子样本成绩不代表全部输入。
