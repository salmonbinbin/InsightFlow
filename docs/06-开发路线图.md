## 下一步具体开发

1. 对示例反馈校验标签，扩充并人工复核500条数据，按开发集/保留集切分，防止调参与测试泄漏。
2. 配置模型供应商、模型名和密钥环境变量；不把密钥提交到项目。
3. 添加 analysis_runs / feedback_analyses 迁移及批次 JSON Schema。
4. 实现 feedback_classifier.py，按20条分批，严格校验返回 ID、枚举及数值范围；记录失败原因和实际 token。
5. 加分析启动与进度 API，用原始反馈完成一轮可重跑分类，再进入 Embedding。

## Sprint 1 评测目标（不是当前成绩）

分类准确率 ≥90%；Intent Accuracy ≥85%；Cluster Purity ≥85%；Evidence Validity ≥95%；Pipeline Success ≥95%。

分类准确率=正确类别条数/已标注条数。Intent 需人工确定同义映射。Purity=各簇内最多真值类别的条数之和/参与聚类条数，同时报告噪声率与簇数，避免全拆成单点虚高。Evidence 分开记录 ID/成员有效率（程序守卫应100%）和语义支持率（人工复核）；Pipeline 成功率=成功运行/全部运行，明确重试口径。

Opportunity Score：coverage25% + severity25% + trend15% + user value20% + business value15%；先归一到0–10。P2<5、P1为5–7.4、P0≥7.5。商业价值由PM填写；缺失趋势/商业价值不得由LLM编造，缺失项处理方案在Sprint2确认。
