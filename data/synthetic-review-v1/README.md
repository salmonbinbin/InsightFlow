# 300条合成输入与100条待审核材料

这套数据由20个设计主题、每主题3种表达及5种使用场景组合而成，共300条不同文本。它用于导入、批处理和标注流程验证，不是真实用户反馈，也不是已经人工复核的黄金集。模板组合会造成高度相似表达，不能据此证明模型对真实业务或新主题的泛化能力。

- `feedback.csv`：直接在上传页面导入的原始输入，来源固定为synthetic_fixture；用户编号和日期均为合成。
- `review-100.csv`：每个主题抽5条，共100条待审核材料。review_status为pending，审核人、分类、严重度和主题标签均留空。不得把设计主题直接复制成“人工确认标签”。
- `groups.csv`：设计分组和候选样本索引，仅用于检查泄漏，不是模型输入或参考答案。按整组划分train/validation/test为180/60/60，主题不跨组；模板措辞仍共享，因此不是独立自然分布测试集。
- `manifest.json`：版本、条数、来源、限制、输入文件SHA-256。旧的两份12条CSV没有覆盖。

使用步骤：

1. 新建一个合成数据项目，上传feedback.csv。实际分类可以在用户配置的模型下发起；本次交付没有代为执行300条真实模型链路。
2. 需要人工评测时，打开评测页，选择已结束的分类或聚类运行，下载该Run的标注模板。
3. 依据原话填写标签，可参考review-100.csv的候选ID选择100条；删除未审核行。填写真实审核人、reviewed状态以及对应阶段的标签。
4. 上传的是**页面下载并填写后的模板**。离线review-100.csv尚无项目和Run绑定，不能直接上传评测，避免同ID串入其他项目或版本。
5. 对同一份输入保存标签版本；修改标签再次上传会新增报告，不覆盖旧报告。标签上传表示你声明完成了该样本复核，不代表整个项目已验收。

分类标签：bug / feature_request / ux_issue / performance_issue / pricing_issue / content_issue / positive_feedback / other。严重度1—5；仅填原话能支持的程度，讨论分歧后再提交。聚类标签由审核者根据同一用户任务/问题定义，相似用词不一定属于同组；本轮不评估自由文本意图准确率。

复现：在backend目录执行`uv run python scripts/build_review_dataset.py --output <新的输出目录>`。目录已存在会拒绝覆盖。生成过程不调用模型、不访问数据库。
